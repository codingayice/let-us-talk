# 领域文档

探索项目之前，先阅读：

- 根目录的 `CONTEXT.md`
- `docs/adr/` 下与当前工作相关的架构决策

如果这些文件尚不存在，继续工作即可；只有在领域术语或架构决策真正确定时，再创建它们。

## 文档布局

本项目采用 single-context 布局：

```text
/
├── CONTEXT.md
└── docs/adr/
```

## 术语约定

需求、issue、规格、测试和代码中的领域概念，应优先使用 `CONTEXT.md` 中定义的词汇。如果新概念尚未进入术语表，记录这一缺口并在需要时通过 domain-modeling 处理。

如果输出与现有 ADR 冲突，明确指出冲突，不要静默覆盖既有决策。
